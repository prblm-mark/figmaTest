## 1. How it differs from the live screen, and why

- **Live has no tabs.** View and Edit are each one stack of collapsible panels. Here **Details** holds
  the panels in live order. The live Stats / Recent Viewers / Referring URLs panels form a **Page
  analysis** tab (Contact View's builder).
- **Every stored version is viewable.** The live Main panel leads Details as a **Main** section: the
  preview, Update file / Generate images, then one card per stored version, each with file name,
  dimensions and size:
  - image: **Master file, Main Image (`_MPreview`), Thumbnail (`_MBrowse`), Original** (the PNG/JPG kept
    when the upload profile converts to WebP);
  - video: **Video file, Thumbnail, Stills** (an MP4's additional assets, each with Set as thumbnail).
  The preview and every card open the **viewer** (DS Modal `--lg`): that version full size (never
  upscaled), its file · size line, "n of N", Previous / Next and ← →, Download. Esc, × or the backdrop
  close it and focus returns to the card. Live opens each version in its `showImage` popup; the viewer
  replaces that.
- **The sidebar is the live info box** (File information): creator, format, size, dimensions, date
  added, downloads, and the production facts. Rows show only when set, as live.
- **No per-field help exists live.** The only help is per panel, from the Media Workflow Profile. It is
  the section's description line, verbatim (typos kept). So there is **no Show help switch** on Media Edit.
- **Edit labels are SiteTextItem keys** (`MediaLiveEdit_*`) whose English values I could not read. The
  View screen's labels for the same fields are used. Please swap in the real text items.

## 2. View

- Header: **Edit** (primary) + **Live view** (secondary); kebab: Add, Copy, Related items, Meta
  information, Monetise, Workflow history, Workflow inbox, Go to list.
- Details sections in live order: Main, Presentation Style, Navigation, Introduction, Main Body, Comments
  and Ratings, Keywords, SEO, Geo-blocking, **Details**, **Production Details**, Search, eCommerce,
  Security, Publication. The live eCommerce panel carries Security and Publication under dividers; here
  each is its own section.
- **Conditions kept:** Details and Production Details are **hidden for images** (that's why there's a
  video item). Main Image is not shown for video types. Not drawn: Permission (documents only),
  Streaming (only with a streaming source), Embed (embeds only).

## 3. Edit

- Header: Cancel · Delete · Save (the kit's edit header; live calls Save "Submit").
- Every MediaAllElements panel in change mode, in order. **Required:** Presentation Style, Album, Title.
- Simplified: **Presentation Style** is a select (live: a thumbnail StyleSelector); **Run Time** is one
  input (live: value + unit select); **Copyright** is read-only (live disables it on change: the credit
  is burnt into the image at upload).
- **Stand-in option lists:** Sponsor Open Link, Geo-blocking Type, Access Type, Media Location, Format,
  Language, Content Security Right. The real ones are SiteTextItem / LookupItem sources.

## 4. Also changed on every record screen: customer signal colours

On Contact View, Account View and Article View (sidebar signals, Analysis ranked list, activity trails,
Recent Viewers):
- Signal circles are now **solid**: `--ao-accent-<hue>-solid` fill with the white `-solid-fg` glyph (was
  the soft scheme). Only hues whose `-solid-fg` is white in both themes are used: bright-teal, lime-radix
  and orange-radix were replaced by muted-teal, green-radix and dark-blue. Lagoon first, blue last, no red.
- The signal row's **"+N" counter** takes Badge Neutral's colours (`--ao-surface-neutral-soft` +
  `--ao-text-neutral`), matching the panel's count chip. Scoped to `.viewer-item__signals`.
- Still demo colouring: live builds draw each signal's own badge image.
