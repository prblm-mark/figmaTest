View-only record sections — Control Centre

What each Control Centre record screen shows on its View screen but not on its Edit screen. Read from the Affino.com source (instance Comrz) via the Hub, 2026-09-25. Every legacy record screen is defined by a *Def.cfm file: one row per field, and slot 9 lists the screens it appears on (l listing, v view, e edit, s search). View-only = v without e, plus rows built only inside a view-mode branch. Fields are grouped by the renderer's dividers: Main · Advanced · Security · Publication · Audit · Other · Notes.

5 · Gaps and caveats

  • AcuCustom timed out (15s) at every level tried; it holds site assets (Sitename/DAM, Skins, Templates...), no CC Def files expected
  • AfcEngine/AfcMessage/CC/SMSProviderProfileDef.cfm is a duplicate copy of AfcMessage and was not parsed separately
  • 22 Def files could not be tied to a ControlProfile (controlProfileCode null): mostly popups/sub-screens (CRMAccountContact, CRMContactListContact, CRMLookupType, RedirectCode, DC_FormStyle, DC_DetailedSectionSettings, Broadbean*, BarredAddress, AfcSecurity ConversionEvent/CustomerLadder (legacy copies of the AfoPromotion ones), UserDef (legacy User screen), StandardStepByStepLookup, AdstxtProfile, Credit, ProductMessage, RenewingOrder, MessageBoard*, Subscriber, ArchiveManagement)
  • 9 screens mapped manually to the closest registered profile because the record view has no profile of its own (e.g. StandardItemDef -> Articles 1097, CRMUserDef -> Contacts 868, CRMAccountDef -> Accounts 867)
  • Rows whose [9] is a variable were resolved by collecting string assignments to that variable in the same file (noted per item); about 70 rows, some unresolved (e.g. variables.BProperties[...][9], modeOrder* vars in Order screens)
  • AfoPromotion/CC/ConversionEventDef.cfm (Customer Signal) reassigns [9] on 42 rows under conditions; overrides are in notes, base value used for classification
  • AfoCommunity/CC/AwardsProfileQuestionDef.cfm builds CProperties twice (two branches); rows from both are included
  • Brace/condition tracking is heuristic (regex state machine); condition text in notes may be truncated or mis-nested in unusual files
  • Only legacy CProperties Def screens are covered. Hub-type profiles (ProfileType 3) and screens not rendered through AfcForm/ViewForm.cfm are not in this inventory. Notably StandardItemDef (Articles) has NO Recent Viewers / Stats / Referring URLs / Index Status rows; those panels exist only on Section, Channel and Edition (and Index Status on Forum Thread)
  • Articles shows none of the analytics panels in this source: Recent Viewers, Stats, Referring URLs and Index Status are defined on Section, Channel and Edition (Index Status also Forum Thread). Articles' view-only items are Live, Created, Created By, Last View and Views. If the Article view shows those panels today, they come from another code path.
  • Mode r (148 rows, mostly the Title link column) is unconfirmed — probably the related-items lookup listing.
  • Hub-type profiles and any screen not rendered through the legacy View/Edit forms are not covered.
